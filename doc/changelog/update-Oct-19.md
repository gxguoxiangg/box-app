# Oct-19 神机卡片修复说明

## 问题确认

Oct-18 虽然增加了父级显示逻辑，但模型假设搜索响应含 department_parent、location_parent1、location_parent2。实际抽查发现搜索只提供 department/location 及其 parent_id，导致父级名称始终缺失。此前测试使用了假设字段，未覆盖真实响应结构。

vendor 已读取，但位置在标题下方，与设计稿原描述标签的位置不符；空值时还会隐藏整个区域。

## 修复

- Repository 通过现有 `/api/v1/tables/department/{id}`、`/api/v1/tables/location/{id}` 读取父级记录。部门展开一层、位置展开两层，依次显示祖父级 · 父级 · 当前位置。
- 单次搜索内共享父级请求，缓存不跨账号或搜索；404 保留可用层级，其他请求错误继续按既有认证/错误流程处理。不递归展开整棵组织树。
- vendor 移回标题右侧标签，空值显示「—」；描述仍显示于卡片右上。
- 用实际响应的 parent_id 结构构造 Mock 测试，覆盖层级补全、请求去重与 404 降级。

## 验证

- 只读联调确认搜索响应结构及部门父级、位置父级、位置祖父级接口能返回名称；未保存真实资产或令牌，联调后注销会话。
- 静态分析 0 问题；既有 101 项测试通过。新增父级查询 2 项测试首次因 Mock 中文响应缺少 UTF-8 声明失败，修正测试响应编码后重新验证通过。
- 本轮未重建 APK，安装测试需要重新构建包含此次修复的版本。
